# VNSA – Modbus register reference (Venus A)

> 🇩🇪 Deutsche Version: [VNSA_Register_Referenz_de.md](VNSA_Register_Referenz_de.md)

Complete, code-verified reference of all 584 registers of the Venus A Modbus map (Control A 1509 (a near clone of D 151; re-checked against Control 151), BMS A 1105 (re-checked against BMS 110 and BMS 115), Micro A 1211 (Novosense NS800RT, contains the PV/MPPT stage)). Every register was traced from its handler or descriptor entry to the origin or consumer of its value and checked for functionlessness; the column *Same as D* compares with the verified Venus D map (`VNSD_Register_Reference.md`). The single source of truth is `VNSA_Register_Map_Final_generated.csv` (columns `status_A`, `gleich_wie_D_A`, `beweisstand_A`, `einheit_skala_A`, `ziel_A`, `leseeffekt_A`, `befund_A`, `gefahr_A`, `suite_empfehlung_A`); this document is generated from it.

Status values as in the D reference: **FUNCTIONAL**, **CONDITIONAL** (only in a special mode / after another write), **NO_OP**, **FUNCTIONLESS** (proven for every device whose firmware is available), **UNKNOWN** (open). Counts: FUNCTIONAL 369, FUNCTIONLESS 136, CONDITIONAL 67, NO_OP 12.

Physical value = raw value × factor (column *Unit / scale*). Registers below 40000 are read-only. *Same as D*: yes = identical meaning, scale and status as on the Venus D; partly = same register but different details (constants, values, origin); no = different behaviour or status.

## 1. Behaviour that applies to many registers

- **The Control is a near clone of the Venus D Control 151** (95.2 % identical, same RAM layout, same Modbus descriptor table and the same Write_Handler except one constant: 44003 is rejected above 1500 W, 44002 accepts up to 2500 W); the Venus A differences sit in compile-time constants (1500 W limits, power classes 800/1200/1500 W, 13 cells per pack, RS485 on USART1 without direction pin, older cloud code) and in the devices behind the Control: the **A micro** (a different MCU and codebase, contains the 4-channel PV/MPPT stage = the class-2 node) and the **A BMS 1105** (SH36735 AFE, 13 cells, other limits).
- **Pack capacity:** the A BMS sends telemetry for packs 1..6 only (`pack_id != 0 && pack_id < 7`; D BMS: 1..9); the Control keeps 7 per-pack records, so pack 7 (34600–34633) exists but always reads 0. Packs count from 1, record indices from 0.
- **Serializer and pair rules of the Control are the same as on D:** signed values the firmware divides by 10/100 lose their sign (only 32101); two-register values must be read as a pair; Modbus TCP exception frames carry MBAP length 4 with only 3 bytes following; versions ≥ 1000 carry one decimal.
- **Energy counters:** the discharge energy is the integral of the power set-point, not a measurement; pure off-grid operation is not counted.
- **PV order:** the Control's PV1 is the micro's PV4 (order reversed); the registers are proven end to end because the micro firmware is available.
- **CAN commands of the Control that the A micro ignores:** 0x18, 0x30–0x3E, 0x40–0x43, 0xFB; the A micro acknowledges but drops power values ≥ 1451 W.
- **Firmware versions (re-check 2026-10-11):** Control 151 serves the same register map as 150.9 (descriptor table byte-identical, `Write_Handler` and read serializer instruction-identical); visible differences: 30200 reads 151, and in anti-feed mode (43000) a positive CT setpoint is reset to 0 while the EPS reserve is active and the meter is queried every 1.1 s instead of 2.0 s. The register path of BMS 110 and BMS 115 is the same as 1105; values differ in the system current limits (32106/35111, 32107/35112: 40.0 A with BMS 110, 50.0 A with 1105/115; 10.0 A charge below 35.00 V own-pack voltage with 1105/115), the charge voltage limit (35110: dynamic only with 1105, constant 46.8 V with 110/115), the version words (30204/34x10/37012: 1100 / 1105 / 115), the SOC end corrections (32104/34x02/37005) and the trip conditions behind Protect1/Protect2/warning words (34x07–34x09). The version per register is given in the CSV column `notiz`. None of these versions changes the reason of a non-functional register.
- **Micro 1211 re-check (2026-10-12):** the two registers that were still open only because the A micro firmware was treated as unavailable are resolved against the Micro 1211 export: 32102 is an exact alias of 30001 (FUNCTIONAL), 45031 has no receiver on any A device (FUNCTIONLESS; the micro ignores 0x100101AA). No A register is UNKNOWN any more.
- **BMS 115 configuration checksum:** the checksum of the BMS configuration block covers its own word, so parameters written over the BMS's own RS485 bus fall back to defaults at the next boot (only A 115). No Modbus register writes these parameters; 45028 (factory reset) writes defaults anyway, so no register write path is affected.

## 4. Open questions

- Sender of CAN id field 0x210100 (BMS RAM lock + outputs off): no available A firmware sends it (not in Control 150.9/151; the Micro 1211 never answers class-2 func 0x00, its class-2 replies use only funcs 0x01-0x04/0x06/0xCB/0xCC/0xFE/0xFF); only an unknown external CAN device could.
- Temperature/current thresholds of the L1/L2 bits live in the BMS config block (defaults said identical to D except the SC stage-1 timeout); not re-derived here.
- Micro 1211 CAN update frames (resolved 2026-10-12, see VNSA_Micro_FW_v1211_Full_Analysis.md section 4.1.6): CAN_RxDispatch@0x08019360 has no class/node check for func 0xCE, but the FlexCAN RX masks only pass id byte1 0x40/0x41 (class 4 node 0/1), 0x21 (class 2 node 1) and the BMS info frames 0x180nAA01; the Control's class-3 BMS update frames (byte1 0x3F/0x3n) are rejected in hardware, so a BMS update cannot start the micro's update routine. Still open: what the A micro bootloader checks before installing a staged image (bootloader not available), and whether an 'mppt' (class 2) update job is ever issued to a Venus A (it would be executed by the micro).
- How a factory-fresh A pack normally gets its master marker (production tool via 45030 or the BMS shell?).
- Real power sign/regulation of the Control's mode-3 class-2 power command during phases 1 and 5 (PV contribution): the Micro 1211 side is known (class-2 func 0x02 mode 3 = MPPT aging mode: stop + restart, power share re-initialised, power reference = commanded W clamped 50..2400 W, ShellCmd_mppt_pow@0x08016428), but how the resulting PV power adds to the battery power in the aging branches of Ctrl_MainControlIsr was not traced in detail.
- Location of the former 'vminnm term' with operand [0x20121b9c]: the operand is g_offGridOutputPowerW of the Micro 1211 (off-grid output power in W, telemetry +0x1A), not PV power; the term itself could not be re-located (the 1211 listing contains no vminnm instruction).
- A front-panel hardware (same TM1650-style driver at I2C addresses 0x68..0x6E?) not verified.
- Tick length of g_tick16b (assumed 1 s) for the limiter period.
- Physical unit of the reply (offset x 0.000791) in 30030: the factor equals the micro's PE-voltage report scale, whose 60 V-class fault threshold maps to exactly 6000 (0.01 V per unit fits); the analog divider is hardware, so the unit stays inferred.
- Exact mapping of frame 2 into 30035 (slot index from frame index).

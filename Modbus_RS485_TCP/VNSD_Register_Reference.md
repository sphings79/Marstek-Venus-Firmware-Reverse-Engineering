# VNSD – Modbus register reference (Venus D)

> 🇩🇪 Deutsche Version: [VNSD_Register_Referenz_de.md](VNSD_Register_Referenz_de.md)

Complete, code-verified reference of all 584 registers of the Venus D Modbus map (Control 147 / 149 / 149.2 / 150 / 151, origin values in Micro 115 / 116 and BMS 117.7 / 118). Every register was traced from its handler or descriptor entry to the origin or consumer of its value and checked for functionlessness (state 2026-10-02). The single source of truth is `VNSD_Register_Map_Final_generated.csv` (columns `status_D`, `einheit_skala_D`, `ziel_D`, `leseeffekt_D`, `befund_D`, `gefahr_D`, `suite_empfehlung_D`, `befund_konfidenz_D`, per-version RAM pointers `source_ptr_v147`…`v151`); this document is generated from it. Details of the formerly unclear registers: [VNSD_Unclear_Registers_Resolution_2026-10-01.md](VNSD_Unclear_Registers_Resolution_2026-10-01.md).

Status values: **FUNCTIONAL** = does what the name says · **CONDITIONAL** = only in a special mode or after another write · **NO_OP** = accepted, no effect · **FUNCTIONLESS** = value constant/never written, or the target never acts, proven for all devices whose firmware is available · **UNKNOWN** = origin proven but meaning not provable, or the peer is a unit without available firmware (class-2/MPPT-type node): such registers stay DEV. Column *proof level* in the CSV (`beweisstand_D`): 'bewiesen' or 'OFFEN'. Counts: FUNCTIONAL 407, CONDITIONAL 76, FUNCTIONLESS 69, UNKNOWN 24, NO_OP 8.

Physical value = raw value × factor (column *Unit / scale*). Registers below 40000 are read-only (FC06/FC10 return exception 2). Names were revised during the verification; the previous name is kept in the CSV column `alt_name` (`frueher: …`).

## 1. Behaviour that applies to many registers

- **Signed values and the read serializer:** values the firmware divides by 10 or 100 before sending lose their sign (`Read_Serializer`, v147–v151); in practice only 32101 is affected (charging reads whole amps, discharging reads garbage). All per-pack registers (34xxx) use scale code 0 and are not affected.
- **Two-register values (u32 / i32) must always be read as a pair.** If the second word is read on its own, the firmware returns part of the *next* field (36103 or 37016 alone return the grid voltage, 37022 alone returns 30028). The per-register fallback after a failed block read therefore returns wrong values for 36000/36001, 36100/36101, 36102/36103 and 37021/37022.
- **Modbus TCP exception frames** carry MBAP length 4 but only 3 bytes follow (all versions): clients wait for a missing byte (see `VNSD_FW_Bug_Exception_Frame_MBAP_Length_2026-09-20.md`).
- **Version words** ≥ 1000 carry one decimal (1492 = 149.2, 1177 = 117.7).
- **Energy counters** (33000–33011) are in 0.01 kWh (u32, two registers); day and month counters follow the device clock, lifetime counters reset only on factory reset.
- **Power-down/reload:** the schedule slots (43100–43129) and the RS485 control mode (42000) live in RAM only; the maximum charge/discharge power (44002/44003) is stored but reads 0 after a restart.
- **Per-pack records (counting pitfall: packs are ONE-based in the BMS and CAN, record indices are ZERO-based):** pack N = CAN unit N = BMS slot N = Control record N−1 (pack 1 is the master's own pack; in the BMS `pack_id` runs 1..N−1 with 0 excluded, e.g. `pack_id < 7` = six packs); each pack has 34 registers (34x00–34x33, x = 0…6); if a slave pack goes offline the master keeps sending its last values.

## 3. Findings for the Marstek Modbus Suite integration (`d.yaml`)

**Wrong definitions (fix):**
- 34x11 `env_temperature`, 34x12 `mos_temperature`, 34x13–34x16 `cell_temperature_1…4` (all 7 packs, 42 entities) are declared `uint16` but are **`int16`** (below 0 °C they show about 6553 °C). 34x07 `protection_1` is `uint16` (bitmask), `cycle_count` should be `uint16`, `mos_status` should be decoded (bit 0 = charge MOSFET on, bit 1 = discharge MOSFET on).
- `battery_total_energy` (32105) is the rated capacity (number of packs × 2560 Wh): use `device_class: energy_storage`, not state_class `total`, and rename.
- `min_cell_temperature` (35011) covers pack 1 only (35010 is the stack-wide maximum): rename or drop.
- `alarm_status` / `alarm_status_low` (36000/36001) and `fault_status_2` (36102/36103) are always 0 on the D; `device_class: problem` is not valid for a sensor. Fault bit texts: in 36101 remove bits 6 and 9 and add bits 0–4 (grid over/under-voltage, over/under-frequency, voltage peak > 430 V); in 36103 add bit 5 (software over-current) and bit 6 (over-voltage > 530).
- `dev_37022` actually reads 30028: replace both DEV entries by one 32-bit register 37021 (count 2). Read the error/alarm pairs 36000/01, 36100/01, 36102/03 only as pairs.
- `work_mode` (30010) is enabled by default but normally reads a stale 0 (refreshed only while `g_maintModeState == 2`); `vms_version` (30202) is the VNS (inverter/Micro) version: “VMS” is a typo for “VNS” (the firmware names its parts vns/ems/mppt/bms, and `vns_boot_version` is already right), so change the display name to “VNS Version” and keep the key, 31000 is the model string (`VNSD-0`), 30301 needs a states map (BLE connection state), remove `dev_30106`, `dev_30110` has the wrong name.
- `schedule_N_start/end` are HHMM values (unit “min” is wrong; step 1 allows invalid values such as xx75 which disable the slot), `schedule_N_mode` is the slot power in W (−1 = self-consumption), 43000 option 2 is the firmware's AI mode (not “trade mode”), 42011 accepts 13–100 (not 10), 44002/44003 must not allow 0.
- Remove the button `factory_reset` (41001 does nothing on the D). Keep the 15 DEV entries 38000–38014 as DEV (disabled by default, never in poll blocks): no sender among the known firmware, but the class-2/MPPT-type unit cannot be excluded (status UNKNOWN); reading them makes the Control broadcast four CAN frames per second until reboot.

**Worth adding (read-only):** 32107 BMS discharge current limit (0.1 A), 32112 BMS error lock (binary sensor), 34x04/34x07/34x08/34x09 decoded BMS state, protect and warning bitmasks per pack, 37000 RS485 slave address.

**Never expose:** 40000, 41000 = `0xAA11`, 41200/42000/42010–42021 only with the safeguards described in section 2, 45000–45031, 46000, 46500–46544, 47001, 47400.

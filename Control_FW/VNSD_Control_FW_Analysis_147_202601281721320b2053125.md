- Image base **0x08004800** (18-KB bootloader below), Nations N32G45x (previously misidentified as Artery AT32F403A,
  see §1a), Keil ARMCC, FreeRTOS, mbedTLS 2.28, cJSON, llhttp, letter-shell. Same codebase as v149–v151.
- v147 is the state **before** the major v149 features: no French counter (TIC), power limit **2200 W**
  instead of 2500 W, 11 instead of 16 Local API methods, 231 instead of 246 Modbus registers, no cloud backup configuration.
- Security posture as in successors: Modbus register 46000 = 0x5100 enables the
  debug shell on RS485 **and TCP 8091** without authentication (§8).

## 1a. MCU identification: Nations N32G45x, not Artery AT32F403A

- The Control/EMS MCU is a **Nations N32G45x with XFMC** (external memory controller), not the previously assumed Artery AT32F403A.
- Evidence: QSPI controller at 0xA0001000 with N32 QSPI_STS bits; RCC PLL multiplier in bits 18–21 + 27 (N32 PLLMULFCT/PLLMULFCT_H); GPIOF/GPIOG in use; SAC crypto coprocessor at 0x40024000 (formerly misnamed "RNGX"); 96-bit UID @ 0x1FFFF7F0; 102 vectors.
- External SRAM 0x60000000–0x60026AF7 runs through XFMC, control registers at 0xA0000000: the official Nations device header `n32g45x.h` (local only, not in the repo) defines `XFMC_REG_BASE 0xA0000000` and `QSPI_BASE = XFMC_REG_BASE + 0x1000`; the Nations driver library contains `n32g45x_xfmc.c`; the firmware itself has the shell command `xfmc_test` (the current English N32G45x user manual incorrectly marks this address space "Reserved").
- Details/header copy: `../Hardware_Recherche/README.md`, `../Hardware_Recherche/MCU_Identifikation/n32g45x.h`.

## 4. Interfaces

### 4.1 Modbus (TCP 502 over CH395, RTU over RS485)
- Descriptor table `g_modbusRegDescTable` (RAM 0x200002F8, `ModbusRegDesc_t[231]`, 12 B/entry: register, source,
  type, scaling, count). Sources without other name are called `g_mbReg<Register>`.
- v149 adds registers **38000–38014** (cumulative energy counters) → v147 does not have them (§9).
- Write path `Write_Handler`: register 46000 (index 999) with 0x5100 = debug mode permanently (EEPROM 0x900);
  0x04D2 / 0x0929 select the YMODEM destination (EMS=1, VENUS=4) — identical to v151.

### 4.2 Local API / MQTT-RPC (`g_mqttRpcMethodTable` @ 0x0805A190, 11 methods)
Marstek.GetDevice (1), Wifi.GetStatus, BLE.GetStatus, Bat.GetStatus, PV.GetStatus, ES.GetStatus, ES.SetMode,
ES.GetMode, EM.GetStatus, Marstek.GetData, DOD.SET (0x0B). v149 adds Ble.Adv, Led.Ctrl, Ota.Set, Set.Ver,
Reset.Factory.

### 4.3 Debug Shell (letter-shell, `shellCommandTable` @ 0x0805E338, 76 entries)
**65** commands (the earlier figure of "63" was inaccurate) + key bindings (←/→, Tab, Backspace 0x08/0x7F,
Delete ESC[3~, Enter) + `help`/`clear`. Access via RS485 debug console and CH395 TCP server port 8091
(after activation, §8). v149 adds `get_backup_datas` and `power_check` → **67** commands.

### 4.4 Cloud
Endpoints under `http://%s.hamedata.com/…` (`/app/neng/`, `/ems/api/v1/get`, `/prod/api/v1/set…`,

`/external-services/api/v1/devices/backup-configs?devid=%s&latest=true`. MQTT over TLS (mbedTLS, authmode 2),
topics `marstek_energy/%s/device/%s/ctrl`.

### 4.5 BLE (Quectel FC41D, AT commands)
Command dispatcher `BLE_App_Command_Dispatcher` (6.6 KB). OTA over BLE: `BLE_Cmd_OTA_Init/WriteSetup/Validate` +
YMODEM — identical to v149 (BLE-OTA possible).

## 5. Power Limits (for the 2500-W question)

- `Config_ClampDefaults_ParamBlock`: maximum charge **and** discharge power are limited to **0x898 = 2200 W**
  (default discharge 800 W, mode 1). v149: 0x9C4 = 2500 W.
- `Config_Apply_WorkModePowerPreset` (v147 only): mode 1 → 800 W, 2 → 600 W, 3 → 2200 W, 4 → 1200 W; removed in v149
  (replaced by the RPC method `Set.Ver` with 800/2200/2500 W).
- `Grid_Export_Power_Limiter`: same structure as v149 (overall clamp 4000 W).

## 6. Structure/Data Findings

- mbedTLS ciphers: `aes_info`, `aes_128/192/256_ecb_info`, `gcm_aes_info`, `aes_128/192/256_gcm_info`,
  `mbedtls_cipher_definitions` (types `mbedtls_cipher_base_t` 24 B, `mbedtls_cipher_info_t` 28 B, Keil 1-byte enums).
- `MQTT_Transport_NullCallback` @ 0x0800FFFC (`bx lr`) is the wait-ready hook of the FC41D transport
  (`MQTT_Server_Config_Select`), not a dead function.
- `Base64URL_Encode` (URL-safe Base64) encodes the AES-ECB-encrypted telemetry body for the HTTP query string;
  exists in v147–149.2, removed from v150 onwards.
- `prvIdleTask` starts at 0x0804C950 (first instruction was previously typed as alignment).
- **Number of BMS packs (applies to 147–151):** 8 pack records in RAM (index 0–7), battery count from CAN clamped to 8,
  Modbus blocks 34000 … 34600 (7 packs), MQTT BMS query accepts index 0–8. The controller's own cell statistic
  `BMS_CellVoltage_MinMax_PerPack` (formerly misnamed `Schedule_MinMax_PerGroup_Calc`) however only covers **6 packs**
  (`pack < 6`, 16 cells each) into the table `g_bmsCellStat<k>…` (6 × 6 B), which `MQTT_Telemetry_String_Formatter`
  outputs. With 7 packs the 7th pack (index 6) is missing from this statistic but is available via Modbus.
- **Pack numbering / offset in the MQTT path (applies to 147–151):** CAN frames of class 0xAA carry the unit in the
  low byte of the ID (`Protocol_AA_CommandDispatch`, only < 9); `CAN_AA_StoreUnit*` write to record `unit − 1`,
  i.e. **CAN unit 1 → record 0**. Modbus 34000 + 100·n and `ShellCmd_get_all_bms_data` (loop 0 … count−1) read
  record n — consistent. `MQTT_Publish_BMS_Data` (MQTT command 0x2A), however, reads **record p** for index p ≥ 1
  (index 0 = totals from PGN 0x1801/0x1802, 0xFF = overview). Consequence: MQTT "BMS(1)" shows CAN unit 2, unit 1
  cannot be queried individually via MQTT, and index 8 (accepted, because only `> 8` is reset to 0) reads past the
  record array — from record offset 0x20 on this is `g_pendingBootDescriptor` (read only, no memory corruption).
  Most likely an off-by-one; whether the app queries 1-based cannot be determined from the firmware. Side finding:
  a 0xAA frame with unit 0 and a unit message type would write to record −1 (into the preceding `g_pgn180x*`
  fields); only triggerable by a faulty CAN node.

## 7. v147 Only / Changed in v149 (Summary; Details in Diff Document)

## 8. Security Findings (Verified in v147)

1. **Unauthenticated Remote Console:** Modbus TCP write access (port 502, without auth) to register 46000 = 0x5100
   → `g_debugMode = 1` permanently in EEPROM → letter-shell on RS485 and TCP 8091 (`CH395_Init_TCPServer_Socket`).
2. **Hard-Coded WiFi Credentials:** `SM471` / `Hame147258` (`ShellCmd_set_wifi`, `Config_LoadOrInit_DeviceSettings`,
   `Quectel_WiFi_AutoConnect_StateMachine`).
3. Cloud upload over unencrypted HTTP (`http://%s.hamedata.com/…`); payload AES-ECB + Base64URL.
